# Official browser benchmark work

The user confirmed beta.4's 2048 win and asked for honest benchmark evaluation on 2026-09-23. The known-good game implementation is preserved at `6de8f8c`; current work is isolated on `benchmark/browser-evaluation`. No perfect score or leaderboard rank has been established.

## Selected track

The initial reproducible track is [WebArena-Verified](https://github.com/ServiceNow/webarena-verified), the 812-task verified release. Its deterministic evaluator and updated environments differ from the [original WebArena](https://webarena.dev/og/) leaderboard. Scores on these tracks must not be presented as interchangeable. The original leaderboard also requires raw per-step observations and predicted actions for submissions.

Pinned upstream commit: `6473f72db5dcefc97b5725b59e734504edc28a21`, package version 1.2.3. The first development pilot is fixed to IDs **0, 11, 41**, the first three distinct task templates on the shop-admin site. It does not establish a full-suite score.

## Evidence boundaries

- The actor gets only the official `agent-input-get` export: task intent, start URLs and public site metadata. The input adapter rejects evaluation/reference fields. Benchmark reference answers and traces are never fed to Jev or the reasoning model.
- The actual Jevry app receives each task through its normal composer API and uses the saved real model connections. Every task gets a new disposable profile and conversation. No task-solving script or model stub is supplied.
- The harness provides the official site's documented login header and starting page. Browser requests are confined to the supplied site origins, excluding environment-control endpoints and the public internet. The agent cannot look up benchmark answers.
- CDP network events, actual Jev request/response pairs, action events and final screenshots are recorded. The official upstream evaluator runs afterward, separately from the actor. A UI status of “complete” is not a benchmark pass.
- Every attempt has a new output directory. Failed attempts are retained. Reports identify development runs, selected task IDs, runtime bundle, source hashes and source changes during execution. Retrying a failed development task does not change an earlier run's score.
- Before any final claim, freeze the implementation, restore the official starting environment, run all selected tasks under one declared protocol, preserve failures, and obtain official evaluation. Mutation tasks require documented environment resets before reuse. The initial pilot only retrieves information.

## Local setup

The local Colima profile `jevry-benchmark` is separate from the user's existing profiles: 6 CPUs, 12 GiB RAM, 400 GiB disk (expanded before the map data installation), Apple Virtualization and Rosetta. It does not change the default Docker context. The official shop-admin image is pinned to `am1n3e/webarena-verified-shopping_admin@sha256:d0531dd27ed98d0c459ff9e88118bf2ed8b660b0ed99c38837db46c065a5be13` and exposed only on localhost ports 7780 and 7781.

The amd64 image's PHP-FPM crashes in OPcache under Rosetta. `scripts/benchmarks/php-arm64.ini` disables opcode caching to let it start. This is a disclosed platform compatibility change, not an evaluator, application-code or dataset modification; it affects server timing, so this setup must not support comparative speed claims.

The JSON configuration contains only the benchmark's publicly documented synthetic credentials. Actual model credentials remain in the OS-encrypted connection store and disposable copies; they are never included in model request traces.

```sh
python3 -m venv artifacts/benchmark-venv
artifacts/benchmark-venv/bin/pip install ./upstream/webarena-verified
artifacts/benchmark-venv/bin/webarena-verified agent-input-get \
  --config scripts/benchmarks/webarena.config.json --output artifacts/webarena-agent-inputs.json

JEVRY_PACKAGED_EXECUTABLE='/absolute/path/to/Jevry.app/Contents/MacOS/Jevry' \
  node scripts/benchmarks/run-webarena.mjs --run-live --tasks=0,11,41 \
  --output=artifacts/webarena/unique-run-name

artifacts/benchmark-venv/bin/webarena-verified eval-tasks \
  --task-ids 0,11,41 --config scripts/benchmarks/webarena.config.json \
  --output-dir artifacts/webarena/unique-run-name
```

The runner preserves raw answers; it removes only an optional surrounding JSON code fence. Invalid JSON remains invalid and must fail grading. Models may consume paid usage. Other benchmark sites must be installed and reset before a wider run; shop-admin, shopping, Reddit and GitLab are provisioned. Exact map and Wikipedia downloads are checkpointed and paused during timing measurements to avoid competing for bandwidth.

## Jev speed work

Primary documentation used: [parallel questions](https://docs.typesafe.ai/patterns/fan-out), [Choice limits and responses](https://docs.typesafe.ai/primitives/choice), [structured instructions](https://docs.typesafe.ai/primitives/advanced), [pre-parsed literal extraction](https://docs.typesafe.ai/cookbooks/pre_parsed_value_extraction_cookbook), [intent routing](https://docs.typesafe.ai/patterns/intent-routing), and [known model limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13). No undocumented caching, session or streaming parameters are assumed.

The first candidate (`speed-001`) shares action policy once, uses short evidence references, groups dropdowns into choices of at most 200 options, copies exact user literals only after Jev selects and validates them, and offers a bounded Jev-only planner for simple observed same-origin navigation. It also includes pagination context, nearby article labels and earlier recovery from repeated ineffective actions. Game control and the preserved beta.4 package remain unchanged.

This candidate initially fans completion evidence choices into every ordinary action request. This is an experiment, not an established optimization: task 0 fell from ten to nine Jev calls, but output tokens rose from 3,435 to 6,634 and Jev time rose from 19.808 to 29.756 seconds. Most of that latency difference occurred in the first three calls. The other completed tasks and a controlled, alternating replay of identical observations must be examined before attributing the timing difference to schema alone. The replay is a model microbenchmark without browser actions; it cannot establish end-to-end task success or a speed record.

The candidate passed 398 tests with real Chromium input enabled and a production build before live evaluation. `artifacts/webarena/speed-001-source.tgz` archives its source. All later attempts use separate directories. Timing comparisons with `fix-005` are descriptive because the earlier run overlapped dataset downloads; server load and the disclosed Rosetta setup also prevent leaderboard speed comparisons.
